# 작품의 연장선으로 만드는 소개 사이트

작품 소개 사이트의 경험·정보 공개 범위·화면 구조를 정할 때 읽는다. 외부 사이트를 분석해 얻은 설계 패턴이며 원본 코드나 일러스트를 복제한 웹 템플릿이 아니다. 작성 양식은 [showcase-design-template.md](../templates/showcase-design-template.md), 배포는 [hosting-showcase-and-banner.md](hosting-showcase-and-banner.md)를 따른다.

## 1. 설계의 출발점: 독자가 접속한 순간 이미 작품 안이다

**사용자 기준: 첫 진입 시 스토리에 온보딩할 정보만 둔다.** 광고 카피·캐치프레이즈·판매 문구를 추가하지 않는다. ‘운명을 선택하라’, ‘당신의 이야기가 시작됩니다’, ‘압도적 자유도’ 같은 문장은 쓰지 않는다. 참고 사이트가 크고 화려해도 정보량과 연출을 전부 가져올 이유는 없다.

첫 방문자가 아래를 이해하면 충분하다.

- 지금 어디이며, 무슨 일이 벌어지고 있는가.
- 나는 어떤 입장에서 시작하고, 무엇을 직접 정할 수 있는가.
- 초반에 마주칠 사람·장소·세력 중 무엇을 알아야 하는가.
- 첫 행동을 하는 데 필요한 공개 규칙은 무엇인가.

초반 이해나 행동에 쓰이지 않는 연대기·전체 인물 도감·전 세계 등급표는 생략한다. 작품명·기록 제목·실제 기능명만으로 탐색이 되면 설명 문구를 더하지 않는다. 초반 정보가 적은 작품은 짧은 문서 하나로 끝내도 된다. ‘작품의 연장선’은 장황한 체험 장치나 세계관 백과사전을 만들라는 뜻이 아니다.

사이트를 ‘작가가 독자에게 설정을 설명하는 페이지’로만 만들지 않는다. 세계 안에 실제 있을 법한 매체를 정하고 독자에게 그 매체를 사용할 이유를 준다. 길드에 들러 의뢰서를 집거나, 단말기를 켜 현장 기록을 읽거나, 누군가 남긴 편지를 펼치는 것이 첫 경험이다.

아래 다섯 질문에 답한 뒤 레이아웃을 고른다.

1. **누가 만들었나?** 협회 기록관, 길드 접수원, 생존자, 신문사 등 문서의 작성 주체.
2. **누가 읽나?** 첫 방문자의 최소 권한과 호칭. 사이트 열람만으로 플레이어의 성별·과거·소속을 확정하지 않는다.
3. **어느 시점인가?** 시작 세트 직전인지, 과거 기록인지. 게시일·관측일·수정일을 구분한다.
4. **왜 읽나?** 의뢰를 고르기 위해, 거점을 찾기 위해, 동료를 알아보기 위해 등 작품 속 목적.
5. **읽고 나면 시작할 수 있나?** 첫 대사·행동을 고르는 데 모르는 전제나 역할 제약이 남아 있지 않은지 확인한다.

한 문장 계약 예: ‘첫 임무를 앞둔 방문자가 거점 접수대의 공개 기록을 읽고, 동행자를 직접 만나 볼 이유를 얻는다.’ 이 문장으로 설명할 수 없는 장식·수치·탭은 역할을 다시 정한다.

## 2. 정보 공개: 정본 지식과 방문자 지식을 분리한다

공개량은 전체 설정의 몇 퍼센트로 정하지 않는다. **시작 상황을 이해하고 선택할 만큼 주되, 플레이로 확인할 답은 남긴다.** 모든 문장은 `story.md`·`characters.md`에서 가져오거나 그 정본이 허용하는 범위에서 쓴다. 공개 설정 변경은 사이트에서 몰래 추가하지 말고 정본에 먼저 반영한다.

| 층위 | 사이트에 둘 수 있는 내용 | 처리 |
|---|---|---|
| 입장 전 필수 안내 | 장르·콘텐츠 등급, 허용되는 역할, 실제 조작법, 플레이 링크 | 쉽게 찾게 두고 허구적 암호로 숨기지 않음 |
| 시작 시점의 공개 사실 | 시민이 아는 사건, 접근 가능한 장소, 공적인 직책, 공개 규칙 | 본문·공고·인물 카드에 수록 |
| 작성자의 관측 | 목격한 행동, 편향된 평가, 관측 당시 상태 | 작성자·시점·근거의 한계를 드러냄 |
| 공개된 소문 | 세계 안에 실제 퍼진 추측, 서로 다른 증언 | 소문임을 표시하고 정답을 확인해 주지 않음 |
| 플레이로 발견할 정보 | 숨은 동기·트라우마 원인·배신·공략 정답·엔딩 조건 | 공개 데이터에서 제외 |
| 운영·제작용 정보 | AI 지시, 키워드 발동 조건, 미공개 이미지 목록, 내부 수치 | HTML·JS·검색·메타데이터에도 포함하지 않음 |

**잠금 연출은 비밀을 보관하는 방법이 아니다.** 봉랍·검열선·기밀 파일 뒤에 실제 비밀 전문을 숨기지 않는다. 존재 자체가 스포일러인 비밀 인물은 잠긴 카드나 ‘미발견 1명’ 집계에도 넣지 않는다. 공개해도 되는 추가 기록만 접어서 보여준다. 성인 콘텐츠 안내와 스포일러 공개는 서로 다른 기준이다.

### 공개 문장을 고르는 네 번의 검사

- 이 작성자는 이 사실을 알 수 있는가?
- 방문자는 이 시점·권한으로 읽을 수 있는가?
- 읽으면 만남·탐색·판단으로 얻어야 할 재미가 사라지는가?
- 단정 대신 관측이나 행동 제안으로 바꿔도 비밀의 존재를 누설하는가?

마지막 질문에도 걸리면 문장 자체를 뺀다. 모든 비밀을 ‘수상하다’, ‘겉모습과 다르다’로 순화해 공개하지 않는다.

### 시점과 불확실성

예정된 축제는 공고로 공개할 수 있다. 그 축제 뒤에 반드시 일어날 습격, 피해 규모, 배신자의 계획은 미래 사건의 정답이므로 공개하지 않는다. ‘경계 강화 공고’도 시작 시점에 실제로 발행된 설정일 때만 쓴다. 능력의 공개 등급과 숨겨진 실제 전력을 구분한다.

신뢰할 수 없는 화자는 세계의 사실을 고쳐 쓰는 허가가 아니다. 작성자의 편향·소문·누락을 표현하되 플레이 방법·콘텐츠 등급·실제 링크 같은 운영 안내는 정확해야 한다. 선택한 기록자의 인칭과 말투를 유지하고, 다른 작성자의 기록에는 서명이나 문서 형식을 달리한다.

## 4. 네 가지 설계 프리셋

아래 크기·색·시간은 참고 사이트의 정확한 측정값이 아닌 새 제작용 시작값이다. 작품이 이미 가진 시각 언어에 맞춰 바꾼다. 공통 정보를 서로 다른 껍데기에 넣는 것만으로 끝내지 말고 문서 작성자·정보 순서·첫 행동까지 함께 바꾼다.

### A. 현장 전술 단말기

- 적합: 재난·사이버펑크·탐사·거점 생존. 독자가 ‘무엇을 알고 나가야 하나’를 묻는 작품.
- 문서 주체: 거점 관제실. 첫 행동: 공개 브리핑 열기.
- 골격: 상단 상태바 → 좌측 구역/인원/위협 탐색 → 우측 선택 기록 → 관련 임무·플레이 안내.
- 화면: 데스크톱 좌측 240~280px, 본문 유동 폭. 모바일은 구역 메뉴를 접고 본문 한 열. 긴 한글 본문은 고정폭 영문 레이블과 다른 읽기 좋은 서체로 둔다.
- 팔레트 시작값: 바탕 `#0B1118`, 패널 `#121F29`, 본문 `#E4EEF2`, 강조 `#73D9E8`, 경보 `#F17E86`. 실제 대비 확인 후 조정.
- 콘텐츠: 위치, 공개 접근 조건, 마지막 관측, 알려진 위험, 현장 행동 팁. 적의 숨은 약점이나 확정 스폰 시간은 정본의 공개 여부에 따른다.
- 핵심 연출: 기록 전환 시 짧은 수신 표시. 가짜 접속 상태는 장식임을 유지하고 실제 사용자의 위치·기기 정보로 꾸미지 않는다.
- 배너: 작품명 또는 기록명 + 호출 부호·상징적인 지형/단말 프레임. 홍보 문장 없이 시작 권한과 맞는 표기를 사용.

### B. 파일 탐색형 기밀 기록

- 적합: 조직·인물 관계·자료 탐색이 중심인 헌터물, 첩보물, 미스터리.
- 문서 주체: 협회 공개 열람실 또는 주어진 접근 권한의 기록관. 첫 행동: 공개 인명록/사건 파일 선택.
- 골격: 경로 표시 → 문서 트리 → 파일 목록 → 상세 기록 → 출처·연결 기록 → 목록 복귀.
- 화면: 문서 번호·등급·표지·공개 요약의 위계. 인물이 많으면 분류와 검색을 먼저 둔다. 탐색 깊이는 기본 2단계에서 시작하고 필요한 경우만 늘린다.
- 팔레트 시작값: 바탕 `#101216`, 종이 대신 판독 패널 `#1B2028`, 본문 `#ECEFF1`, 보조 `#ADB5C1`, 기밀 표시 `#E79282`.
- 콘텐츠: 신원·공적 소속·관측 기록·공개 평가. 성격 유형·정확한 호감도·진짜 목적은 자동 수록하지 않는다.
- 핵심 연출: 파일 열기·가림막·문서 도장. ‘기밀 해제’ 클릭 뒤에는 공개 가능한 기록만 나온다. 비밀을 풀기 위한 비밀번호 게임을 필수 정보 앞에 두지 않는다.
- 배너: 작품명·문서명이 있는 표지 형태. 조작 설명이 필요하면 ‘기록 열기’처럼 실제 기능만 표시.

### C. 의뢰 게시판과 이야기꾼의 기록

- 적합: 길드·판타지·일상 사건·선택의 매력이 중요한 작품.
- 문서 주체: 접수원 또는 이야기꾼. 첫 행동: 의뢰서 한 장 펼치기.
- 골격: 3~6개의 의뢰/소문 카드 → 선택한 공고 전문 → 짧은 서장 → 공개 세력/인물 → 시작 안내. 장 수는 예시이며 작은 화면에서는 한두 열로 바꾼다.
- 화면: 목재·종이·잉크의 역할을 구분한다. 불규칙한 종이 외곽과 기울기는 장식 레이어에 적용하고 본문 가독성·클릭 영역을 유지한다.
- 팔레트 시작값: 목재 `#35281E`, 종이 `#F2E5C2`, 잉크 `#34281F`, 봉랍 `#8D3930`, 보조 잉크 `#675744`.
- 콘텐츠: 의뢰 목적·공개 위험·보수 또는 보수 미정·접수원의 한마디. 카드만 읽어도 어떤 행동을 상상해야 할지 보이게 한다.
- 핵심 연출: 종이 펼침·봉랍 개봉. 실제로 다른 루트와 연결하지 않는다면 ‘의뢰 수락 완료’ 대신 ‘의뢰서 펼치기’로 부른다. 플레이어의 행동을 사이트가 이미 실행한 것처럼 쓰지 않는다.
- 화자 예: ‘철문 앞에서 세 번 두드리게. 네 번째부터는 경비가 성을 내거든.’ 규칙과 목소리를 같이 전달하되 정본에 없는 규칙은 만들지 않는다.
- 배너: 못으로 붙인 공고나 편지 형태. 작은 화면에서 제목과 공개 공고만으로 성립하도록 구성한다. 유인 문구는 넣지 않는다.

### D. 서사형 기록관과 인물 도감

- 적합: 시대 전환·여러 세계·다수 인물로 구성된 장편. 전체 분위기와 자료 탐색이 모두 필요할 때.
- 문서 주체: 기록관 또는 편찬자. 첫 행동: 사건의 첫 기록 읽기 / 인물 도감 바로 가기.
- 골격: 장면처럼 시작하는 첫 화면 → 전환점 3~5개 → 공개 세계 원리 → 세력/장소 → 별도 인물 도감 → 플레이 연결.
- 화면: 큰 제목과 넓은 여백은 도입에 사용하고, 도감은 일관된 카드와 필터로 정돈한다. 제목의 한글 한 글자만 다음 줄에 남지 않게 폭과 크기를 조절한다.
- 팔레트 시작값: 바탕 `#10131E`, 본문 `#ECE8DB`, 보조 `#ACB7C8`, 강조 `#88D0DC`, 이계 포인트 `#A898E5`.
- 콘텐츠: 사건이 현재 생활을 어떻게 바꿨는지, 그 변화 속에서 플레이어가 할 수 있는 선택. 미래의 확정 연표 대신 시작 이전 사건과 공표된 일정으로 구성한다.
- 핵심 연출: 섹션별 전경·짧은 전환·대표 인물 연결. ‘힘의 계통 → 해당 계통 인물 → 소속 장소’처럼 의미 있는 링크를 만든다.
- 도감: 공개 소속·역할·한 줄 인상으로 탐색. 검색/필터/정렬을 조합하고 상세에서 돌아오면 결과와 위치를 복원한다. 세계 수·인물 수는 공개 데이터에서 계산한다.
- 배너: 사건을 상징하는 풍경과 작품명 또는 기록명. 사이트의 첫 화면과 같은 색·서체 계열로 연결한다.

### 선택과 혼합

주된 형식 하나를 먼저 고른다. A의 외관과 B의 문서 탐색은 잘 연결되고, D의 도입과 B의 도감도 함께 쓸 수 있다. C의 종이 게시판을 쓰는 작품에서 이유 없이 해킹 콘솔로 바꾸지 않는다. 자료 수가 적은 작품에는 검색·여러 하위 페이지·긴 입장 연출을 자동 추가하지 않는다.

## 5. 작품에서 사이트로, 사이트에서 플레이로

사이트의 각 구역은 첫 진입에 필요한 정보를 전달한다. 아래 질문은 설계자가 정보의 쓰임을 점검하는 용도이며, 화면에 질문이나 후크를 추가하라는 뜻이 아니다.

| 구역 | 알게 되는 것 | 남겨둘 질문 |
|---|---|---|
| 거점 공고 | 당장 부족한 자원과 도움 요청 | 누구를 도우러 갈까? |
| 인물 기록 | 공개 역할과 관찰 가능한 태도 | 직접 만나면 어떤 사람일까? |
| 소문 모음 | 증언이 엇갈린다는 사실 | 어느 말을 믿고 확인할까? |
| 사건 연표 | 현재 갈등을 만든 과거 | 나는 그 갈등에 어떻게 관여할까? |

질문은 매 문단의 의문문으로 강제하지 않는다. 기록이 멈추는 지점이나 상충하는 공개 증언으로도 남길 수 있다. 정답을 흰 글씨·숨김 태그·이미지 파일명에 넣지 않는다.

사이트의 선택을 게임에 넘기는 방식도 명시한다. 실제 연결이 없으면 문서 열람으로 끝내고 원할 때 첫 입력에 쓸 문장을 제안한다. 복사 버튼은 사용자가 눌렀을 때만 동작하며, 크랙 상태가 자동 저장되었다고 말하지 않는다. 여러 시작 세트가 있으면 해당 세트에서 허용하는 역할과 시간에 맞춰 안내한다.

## 6. 연출의 경계와 제작 완료 기준

- 입장 연출은 첫 만남의 한 동작으로 끝낼 수 있게 한다. 기본 제작 목표는 1초 안팎이며 건너뛰기·재방문 생략을 제공한다. JS나 오디오 실패가 본문을 영구히 가리지 않게 한다.
- 음악은 선택 가능하게 하고 재생/정지 상태를 정확히 표시한다. 열람 클릭과 음악 선택을 구분하거나 클릭 전에 재생 사실을 분명히 알린다. 음소거해도 모든 의미가 전달되어야 한다.
- 스캔라인·깜박임·흔들림·타이핑은 분위기보다 읽기를 방해하지 않게 제한한다. 동작 줄이기 설정에서는 즉시 전환한다.
- ‘펼치기·닫기·뒤로·검색·플레이하기’는 터치와 키보드로 작동해야 한다. 장식용 파일명만으로 기능을 설명하지 않는다.
- 게시판·단말기·도감의 형태가 달라도 내용은 텍스트로 읽을 수 있어야 한다. 배너에 모든 안내를 구워 넣지 않는다.

검증은 세 방문으로 한다: **처음 온 사람**은 역할과 갈등을 알고 첫 행동을 고를 수 있는가; **다시 온 사람**은 연출을 반복하지 않고 원하는 기록을 찾는가; **정본을 아는 검토자**는 숨은 답·미래 확정 사건·내부 설정의 누출을 발견하는가. 추가로 390px/데스크톱, 음악 꺼짐, 동작 줄임, 이미지 실패, 상세 직접 링크와 뒤로 가기를 확인하고 수행하지 못한 것은 미확인으로 남긴다.

## 7. 실행 가능한 기본 템플릿

[showcase-sites/](../templates/showcase-sites/README.md)에 HTML/CSS 3종이 있다. 전술 단말기(A), 길드 게시판(C), 기록관(D)의 기본 구현이며, 파일 탐색형(B)은 이 문서의 설계 프리셋으로 제공한다. 새로운 사이트가 필요하면 세 폴더 중 하나를 복사해 시작할 수 있다. 고유 작품 문구·이미지를 복제한 템플릿이 아니며 샘플 설정은 실제 작품의 정본으로 교체한다.

## 8. 실행 순서

1. 정본과 시작 세트를 읽고 사이트의 작성자·시점·방문자 권한을 정한다.
2. [설계 양식](../templates/showcase-design-template.md)을 `build/assets/showcase-brief.md`로 복사해 공개 정보 장부부터 채운다.
3. 프리셋 하나를 선택하고 첫 화면·인물 상세·모바일 탐색을 먼저 설계한다. 정보량과 화자 목소리가 성립한 뒤 장식과 전환을 더한다.
4. 새로운 작품 문구와 사용 가능한 이미지로 제작한다. 참고 사이트의 원본 이미지·음원·로고·고유 문구를 그대로 가져오지 않는다. 광고성 카피는 새로 쓰지 않는다.
5. 공개 데이터만으로 갤러리·통계·검색 인덱스를 만들고 배너·크랙 상세설명과 맞춘다.
6. 세 방문 검토와 화면 검증 후 호스팅 지침으로 이어간다. 사이트 설계 완료, 구현 완료, 배포 완료를 구분한다.
