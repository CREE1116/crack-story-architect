# 5. 크랙 파생 에셋 폴더 및 쇼케이스 바이블 (Derived Assets & Showcase)

이 문서는 크랙 플랫폼 배포 및 플레이어 온보딩을 위한 **`build/assets/` 디렉토리 필수 산출물 체계**, **상세설명란·댓글 분리 원칙**, **유저 정보 한도 준수 플레이 팁**을 소유합니다.

---

## 📁 1. `build/assets/` 공식 디렉토리 규약

`build/assets/`는 모델 프롬프트로 주입되는 시스템 프롬프트가 아니라, **크랙 등록 웹페이지 입력과 플레이어 온보딩, 이미지 생성을 위한 파생 산출물(Derived Production Inputs)**을 모아두는 필수 디렉토리입니다.

```text
build/
  integrated-prompt-safe.md    # 모델 주입용 통합 프롬프트 (전연령)
  integrated-prompt-unsafe.md  # 모델 주입용 통합 프롬프트 (성인)
  keyword-book*.md             # 모델 주입용 키워드북
  prologue.md                  # 기본 시작 세트 사본
  start-prompt.md              # 기본 시작 세트 사본
  assets/                      # 🌟 크랙 파생 에셋 공식 디렉토리
    ├── story-description.md   # 크랙 상세설명란 (마크다운: 배너·사이트·자산표·단축어, 설정 설명 금지)
    ├── summary-comment.md     # 크랙 첫 고정 댓글 (평문: 식별번호 명부·이미지 양식/코드·상태창 범례·시작 팁)
    ├── play-guide.md          # 크랙 [시작 설정] 탭 플레이어 안내문
    ├── recommended-replies.md # 세트 공통 첫 추천 답변 3종 (--- 구분)
    ├── build-stamp.json       # 컴파일 시점 소스 해시 기록
    ├── characters.json        # NAI 가중치 베이스 프롬프트 + UC JSON (GREED 표준)
    ├── image-prompts.md       # 단부루 검증 공식 태그 기반 일러스트 프롬프트 시트
    ├── prompts.json           # 기계 판독용 이미지 프롬프트 JSON
    ├── character-design.md    # 인물 시각 디자인 명세표
    └── scene-design.md        # 배경 및 장면 시각 디자인 명세표
```

## 🌐 2. 상세설명란 vs 고정 댓글 절대 분리 원칙

크랙에는 작품을 소개하는 칸이 **세 개** 있으며, 렌더링 방식과 목적이 완전히 다릅니다:

| 필드 | 반영 위치 | 렌더링 | 글자 수 / 분량 | 수록 내용 |
|---|---|:---:|:---:|---|
| **한 줄 소개 (Logline)** | 목록 카드·검색 결과 | 텍스트 | **정확히 30자 이내** | 클릭을 유도하는 후크 한 문장 (줄거리 요약 금지) |
| **상세설명 (Description)** | 작품 상세 페이지 본문 | **마크다운 O** | 컴팩트 (3초 스캔) | 배너 / 사이트 링크 / 이미지 자산 표 / 단축어 / 제작자 코멘트 |
| **고정 댓글 (Summary Comment)** | 작품 발행 후 첫 댓글 | **플레인 텍스트** | 넉넉한 분량 | 식별 번호 명부·이미지 출력 양식과 코드·상태창 읽는 법·시작 팁 |

### ① 상세설명란 (`build/assets/story-description.md`)

상세설명은 **작품 설정을 설명하는 곳이 아니다.** 세계관 문단, 줄거리, 시작 설정 표, 플레이 가이드 문단을 넣지 않는다. 설정은 배너가 연결하는 소개 사이트가 맡는다. 아래 순서만 쓴다.

```markdown
[![작품명](https://도메인/banner.webp)](https://도메인)

> **[<사이트 이름> 열기 ▸](https://도메인)** — 사이트에 무엇이 있는지 한 줄. 플레이 전에 읽으면 첫 입력이 쉬워집니다.

## 📊 이미지 자산

| 구분 | 🖼️ 전연령 | 🔞 성인 |
| --- | ---: | ---: |
| ♀ N명 (공개 인물 이름 나열) | 인물당 N장 (s00~sNN) | 인물당 N장 (a01~aNN) |
| 배경 | N장 (bg01~bgNN) | — |
| 몬스터·이벤트 등 | N종 N장 | — |
| **합계** | **전연령 N장** | **성인 N장 (총 N장)** |

## ⚡ 단축어

- **이름** 한 줄 설명 · **이름** 한 줄 설명 · …
- `/OOC` 로 언제든 대화 밖에서 설정을 묻거나 교정할 수 있습니다.

## 💬 제작자 코멘트
```

- **제작자 코멘트는 제작자가 직접 쓴다.** 에이전트는 제목만 두거나 빼고, 대신 문구를 지어 넣지 않는다.
- 이미지 자산 표에는 **공개 인물만** 넣는다. 존재 자체가 반전인 인물(숨은 적·정체불명 신격)은 이름을 빼고, 정체를 모르는 인물은 공개 호칭(예: "은백 머리 여자애")으로 적는다. 합계에서 뺐다면 작성자에게 그 사실을 알린다.
- 배너 alt 는 작품명, 링크 대상은 소개 사이트 루트. 단축어 이름은 실제 등록된 이름과 정확히 같아야 한다.

### ② 고정 댓글 (`build/assets/summary-comment.md`)

크랙 댓글창은 **마크다운을 렌더링하지 않는다.** `**`·`##`·표는 깨진다. 대신 이미지 출력 양식의 `![img](...)` 는 **유저가 따라 쓸 문법 그 자체**라 그대로 적는다. 섹션마다 `━` 구분선과 이모지 제목, 섹션 사이 빈 줄 두 줄로 읽기 편하게 만든다.

```text
━━━━━━━━━━━━━━━━━━━━
📇 인물 명부 · 식별 번호
━━━━━━━━━━━━━━━━━━━━

▸ 소속 A (한 줄 성격)
01 이름 · 직책 (나이)
02 이름 · 직책 (나이)

▸ ???
15 공개 호칭 · 한 줄

※ 등장인물은 전원 성인입니다. (제외 대상이 있으면 명시)


━━━━━━━━━━━━━━━━━━━━
🖼️ 이미지 출력 양식 · 코드
━━━━━━━━━━━━━━━━━━━━

▸ 인물
![img](https://도메인/식별번호/코드.webp)
예) ![img](https://도메인/04/s03.webp) → 이름 · 웃음

전연령
s00 명함
s01 차분　　s02 호감　　s03 웃음
…
※ 예외 인물의 보유 범위 (예: 15는 s00~s11까지)

성인 (19+ 판)
a01 …　　a02 …　　a03 …

▸ 배경
![img](https://도메인/bg/bg번호.webp)
bg01 장소　bg02 장소
…

▸ 몬스터·이벤트
![img](https://도메인/ray/r번호e.webp) → 출현
D급 r01 이름　r02 이름

▸ 언제 나오나요?
· 장소에 들어서면 본문 맨 위에 배경
· 인물이 처음 나오면 명함, 이후엔 대사마다 감정 컷
· 이름 없는 인물과 당신에게는 이미지가 없습니다


━━━━━━━━━━━━━━━━━━━━
📟 상태창 읽는 법
━━━━━━━━━━━━━━━━━━━━

⌛ 응답 수　💰 현금　🔗 소속
날씨　☀️ 맑음　☁️ 흐림　🌧️ 비 …
위치　🏠 집　🏢 실내 …
신호　🔰 평상　⚠️ 긴장·대치　⚔️ 교전 …
관계 (나쁨 → 좋음)
😠 갈등 → 🤨 경계 → 😐 초면 → 🙂 호감 → …

※ 관계가 움직이는 조건, 상태창 칸 중 헷갈리는 것(공식 기록 vs 실제 수치) 한두 줄


━━━━━━━━━━━━━━━━━━━━
💡 알고 시작할 것
━━━━━━━━━━━━━━━━━━━━

· 첫 입력에 적을 것
· 핵심 선택 루프 한 줄
· 소속·자유도 한 줄

단축어
이름 설명　이름 설명 …

소개 사이트 → 도메인
```

- **식별 번호 = 이미지 폴더 번호 = 프롬프트 명부 번호.** 셋이 어긋나면 유저가 쓴 이미지가 엉뚱한 인물로 뜬다.
- 이미지 출력 양식과 코드표는 **한 섹션**에 둔다. 인물·배경·몬스터마다 "양식 한 줄 → 예시 → 코드표" 순서.
- 상태창 범례는 통합 프롬프트 `# 표기` 의 이모지를 **빠짐없이** 풀어 쓴다. 관계 단계는 화살표 사다리로.
- 코드표는 3열 격자(전각 공백 `　` 정렬)로 쓴다. 한 줄에 다 붙이면 모바일에서 못 읽는다.
- 세계관 설명은 짧게 두거나 사이트 링크로 대신한다. 2,500자를 넘기면 크랙 댓글 한도에 걸리는지 등록 때 확인한다.
- 숨은 인물(명부 16~19 같은 반전 인물)은 명부·코드표에서 뺀다. 번호만 `??? · 비공개` 로 남길지는 작성자에게 묻는다.

## 🎯 3. 30자 한 줄 소개 (Logline) 후크 공식

- **플랫폼 제한**: 정확히 **30자 이내** (공백 포함).
- **작성 원칙**: 줄거리 설명 배제. **[역설적 상황] + [호기심 유발 질문/도전]**
  - ⭕ *"멸망한 서울, 까칠한 분대장과 살아남기"* (21자)
  - ⭕ *"야간 편의점, 손님들이 사람이 아니다"* (20자)
  - ❌ *"2035년 갑자기 서울에 차원 게이트가 열려 몬스터들이 몰려오는데..."* (줄거리 나열 ➔ 탈락)

## 🛡️ 4. 정보 공개 한도 (Information Horizon) & 플레이 팁 치환 공식

> [!CAUTION]
> 작성자(AI)는 `story.md`와 `characters.md`의 모든 비밀(흑막, 배신자, 트라우마 원인, 게이트 진실)을 알고 있습니다.
> 하지만 이를 **상세설명이나 가이드에 털어놓는 것은 게임의 탐험과 발견 재미를 파괴하는 최악의 스포일러**입니다.

### ① 공개 / 비공개 2분할 경계선
- **공개 대상 (Day 1)**: 표면적 세계관, 시작 신분·거점, 관찰 가능한 첫인상 및 말투, 시스템 조작법.
- **절대 비공개 (In-game Discovery)**: 인물의 숨겨진 과거사, 역린의 원인, 흑막의 목적, 히든 엔딩 조건.

### ② 스포일러 ➔ '플레이 팁(Play Tips)' 4대 치환 세트

설명 대신 플레이어의 상호작용과 탐색을 돕는 **4대 행동 팁**을 수록합니다:

1. **💡 동료 교감 팁**:
   - ❌ *"차세은 실무관은 측정 공백자들을 몰래 도왔던 비밀 장부를 숨기고 있습니다."*
   - ⭕ *"겉으로는 피곤해 보이거나 조건부터 따지는 인물들이라도, 그들의 계산 너머 사정을 존중할 때 뜻밖의 신뢰가 쌓입니다."*
2. **💡 생존 & 탐색 팁**:
   - ❌ *"뒷골목 와인바 펭귄 지하에 가면 장물 캐시 유통 브로커가 있습니다."*
   - ⭕ *"도시 탐색 중 소문이나 수상한 구역을 발견하면 그냥 지나치지 마세요. 뜻밖의 의뢰나 활로가 열릴 수 있습니다."*
3. **💡 자원 & 상태 관리 팁**:
   - ❌ *"캐시를 흡수하면 증거 소멸로 바운티 정산이 0원이 됩니다."*
   - ⭕ *"하단 상태창의 소지 캐시와 현금을 수시로 확인하세요. 캐시를 팔아 장비를 맞출지, 몸에 흡수해 다음 이능을 피울지의 선택이 당신의 길을 결정합니다."*
4. **💡 자유도 & 명령어 팁**:
   - ⭕ *"정해진 선택지는 없습니다. 엄폐물을 이용한 전술적 우회, 도발, 설득 등 창의적인 행동을 자유롭게 시도해 보세요."*


## 5. 등록용 원고를 완성하는 순서

배너·소개 사이트 제작이나 이미지 호스팅이 필요하면 [hosting-showcase-and-banner.md](hosting-showcase-and-banner.md)를 함께 읽는다. 위 템플릿의 인물 수·이미지 수·등급 분포·단축어는 예시이며 그대로 복사하지 않는다.

1. 정본에서 Day 1 공개 정보와 플레이어 역할을 추린다. 후크는 ‘내 역할 + 상황의 모순 또는 선택 압박’으로 쓰고 공백을 포함해 실제 글자 수를 센다. 이 저장소의 한 줄 소개 목표는 30자 이내다. 플랫폼 입력 상한은 실제 등록 화면에서 재확인하며 참고 저장소의 80자 표기를 섞지 않는다.
2. 공개 이미지 목록을 실제 파일과 대조해 일반·성인·배경·이벤트 수를 집계한다. 인물별 장수가 다르면 개별 행이나 범위로 표시한다. 배너·썸네일·명함·중복 크롭을 CG 수에 포함하는지는 명시하고 미생성·미배포 파일은 완성 수량에서 뺀다. 성별로 분류할 필요가 없으면 인물·소속별로 집계한다.
3. 상세설명은 ①의 순서(배너 → 사이트 링크 → 이미지 자산 표 → 단축어 → 제작자 코멘트 제목)만 쓴다. 이미지가 없으면 배너·자산 표를 억지로 만들지 말고 소개 링크와 단축어만 둔다. 제작자 코멘트 본문은 작성자 몫이다.
4. 단축어는 실제 등록된 키워드북의 트리거와 기능만 안내한다. `/OOC`도 지원 여부를 확인한다. 숨은 속마음 공개, 무조건적 이미지 출력, 모든 역할 선택 가능 같은 미구현 기능을 약속하지 않는다. 입력 예는 실제 시작 세트가 허용하는 역할로 작성한다.
5. 고정 댓글은 ②의 순서(식별 번호 명부 → 이미지 출력 양식·코드 → 상태창 읽는 법 → 알고 시작할 것)를 평문으로 쓴다. 이미지 코드표와 상태창 범례는 빠짐없이 쓴다. 유저가 직접 `![img](...)` 를 쓰거나 상태창을 해석하는 데 필요하다.
6. 실제 배너 링크와 수량을 반영한 등록용 원고를 저장한다. `OO명`, 예시 이름, 미확정 URL을 제거하고 상세설명의 마크다운 렌더링과 댓글의 평문 가독성을 각각 확인한다. 웹 등록·댓글 게시가 요청되지 않았다면 붙여 넣을 원고를 전달한다.

### 문구 품질 기준

- 후크는 연대기 요약보다 플레이어가 당장 겪는 모순을 보여준다. 예: ‘야간 편의점, 손님들이 사람이 아니다’.
- 플레이 안내는 추상적인 ‘높은 자유도’ 대신 가능한 행동을 보여준다. 예: ‘첫 입력에 역할을 적고, 대사와 행동으로 상황을 이어가세요.’ 역할 선택이 허용된 작품에만 쓴다.
- 제작자 코멘트에는 작품을 즐기는 데 도움이 되는 의도나 실제 피드백 안내를 짧게 쓴다. 사용자가 말하지 않은 업데이트 주기·응답 기한·연락처를 만들지 않는다.
- 사이트·배너·상세설명·댓글에서 작품명, 인물 표기, 수량, 시작 신분, 등급 안내를 맞춘다. 내부 설정을 완곡한 팁으로 바꿨더라도 비밀의 존재나 정답을 암시하면 삭제한다.
