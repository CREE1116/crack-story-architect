# 5. 플랫폼 규격 및 검증 가이드 (Platform Spec & Lint)

크랙 플랫폼의 기술적 제약, 글자 수 계산법, 시각 태그 추출, 단축어 및 배포 전 최종 검증 체크리스트를 다룹니다.

---

## 1. 플랫폼 분량 상한 및 측정 규격

| 산출물 | 플랫폼 슬롯 | 분량 상한 | 측정 기준 |
|---|---|---|---|
| **통합 시스템 프롬프트** | 통합 프롬프트 (SAFE / UNSAFE) | **≤ 7,000자** | 문자(Character), 공백/줄바꿈 포함 |
| **프롤로그** | 프롤로그 란 | **≤ 1,000자** | 문자(Character), 공백/줄바꿈 포함 |
| **시작 프롬프트** | 시작 프롬프트 란 | **≤ 1,000자** | 문자(Character), 공백/줄바꿈 포함 |
| **키워드북 항목** | 키워드북 개별 항목 본문 | **≤ 400자** | **UTF-16 코드 유닛 (이모지=2자 취급)** |
| **한 줄 소개** | 목록 카드 로그라인 | **≤ 30자** | 30자 초과 시 말줄임표 잘림 |
| **플레이 가이드** | 시작 설정 플레이 가이드 란 | **≤ 500자** | 500자 초과 시 하단 잘림 |

> [!WARNING]
> **UTF-16 코드 유닛 주의**: 대부분의 이모지(🥰, ⚔️, 💰, 🏢)는 서러게이트 페어로 2단위를 차지합니다. 파이썬 `len(text)`(코드포인트)보다 UTF-16 기준 길이가 더 길어 플랫폼에서 잘릴 수 있으므로 반드시 `max(codepoints, utf16_units)`로 검사합니다.

## 2. 핵심 시각 태그 (Visual Tags) 추출법

인물의 일러스트 및 외형 일관성을 유지하기 위해, 각 인물당 **핵심 3~4개 식별 태그**를 고정합니다:

1. **헤어 3요소**: 길이 + 스타일 + 색상 (예: `dark auburn hair, long hair, low ponytail`, `short messy coral pink bob`)
2. **눈동자 색상**: (예: `amber eyes`, `violet eyes`, `navy blue eyes`)
3. **대표 복장**: (예: `dark brown leather apron, black turtleneck`, `avant-garde monochrome blouse, corset vest`)
4. **고유 특징/장비**: (예: `mechanical gauntlet, cyan glowing circuit lines`, `long metal tool staff, amber cache crystal`)

- 태그가 너무 많으면 NovelAI 등 생성 엔진에서 특징이 뭉개집니다. 3~4개의 고유 특징에 집중합니다.

## 3. 프로덕션 대표 단축어 6종 레시피 (Shortcuts)

단축어는 플레이어가 채팅창에서 버튼 클릭 한 번(또는 `/단축어` 명령어)으로 AI에게 특수 지시를 내리는 **1회성 인터랙션 리모컨**입니다.  
`build/keyword-book.md`의 `# Shortcuts (단축어)` 섹션에 등록하면 자동 동기화 도구(`crack_sync.py`)가 크랙 스튜디오에 100% 자동 등록합니다.

### ⚠️ 단축어 4대 불변 규칙
1. **이름 앞 슬래시(`/`) 절대 금지**: 크랙 UI는 단축어 버튼 클릭 시 자동으로 `/`를 붙여서 전송합니다. 이름에 `/`를 쓰면 `//사칭교정`처럼 이중 슬래시가 되어 명령어가 인식되지 않습니다.
2. **엄격한 플랫폼 한도**: 이름 **≤ 10자** (권장 2~4자), 설명 **≤ 30자**, 프롬프트 **≤ 400자 (UTF-16 기준)**.
3. **메타형 vs 서사형 구분**:
   - **메타형 (`요약`, `OOC`, `상태점검`, `사내망`)**: `"RP 즉시 중단"`, `"새 장면 이어쓰기·소설 서술 금지"`, `"캐릭터 비인지"`를 반드시 명시합니다.
   - **서사형 (`다음날로`)**: 소설 서술문을 유지하며, 인물이 시간 경과를 인지하고 유저의 첫 행동 여백을 남깁니다.
4. **경제성 원칙 (1호출 = 1크래커 소모)**:
   - 매 턴 하단 ````UI````에 찍히는 체력/자원을 그대로 되풀이하는 단순 `상태창` 단축어는 재화 낭비이므로 만들지 않습니다. 확실한 편의와 가치를 제공하는 기능만 선별 등록합니다.

### 📋 대표 단축어 6종 실전 레시피

#### 1. `OOC` (메타 설정 질의 / 오류 진단)
* **슬러그**: `ooc` | **이름**: `OOC` | **설명**: `IC 중단 후 오류 원인과 조치 보고`
```markdown
## ooc
- name: OOC
- description: IC 중단 후 오류 원인과 조치 보고
- prompt:
IC 출력 전면 중단. {user}가 재개를 말하기 전까지 장면 진행 금지.
-인간인 척·사과·감정형 멘트("죄송합니다" 등) 배제.
-지적받은 사실을 그대로 읊어 분량 채우기 금지.
-아래 3단으로만 건조하게 보고:
·오류: 확인된 문제 1줄
·원인: 기술적 원인(지시 충돌/컨텍스트 누수/토큰 매칭 실패 등)
·조치: 수정된 결과값과 그 도출 과정
-확실치 않으면 추정, 모르면 모른다고 명시. 지어내지 않는다.
```

#### 2. `요약` (서사 압축 브리핑)
* **슬러그**: `summary` | **이름**: `요약` | **설명**: `공개된 최근 사건을 압축 요약`
```markdown
## summary
- name: 요약
- description: 공개된 최근 사건을 압축 요약
- prompt:
이번 응답만 요약을 낸다. 롤플레이 즉시 중단.
-새 장면 이어쓰기·훈수·지어내기 금지.
-지금까지 대화에서 실제로 공개·확정된 사실만 아래 4항목으로 각 1줄씩 요약:
1) 현재 날짜와 시각
2) 현재 위치 및 현장 인원
3) 주연 인물들과의 핵심 관계 단계
4) 아직 해결되지 않은 당면 과제
-각 항목 1줄, 전체 300자 이내. 다음 응답부터 통상 진행으로 복귀한다.
```

#### 3. `사칭교정` (PC 주권 침해 즉시 교정)
* **슬러그**: `fix_impersonation` | **이름**: `사칭교정` | **설명**: `{user} 대사·행동 임의 대필 교정`
```markdown
## fix_impersonation
- name: 사칭교정
- description: {user} 대사·행동 임의 대필 교정
- prompt:
[시스템 경고] 방금 응답에서 {user}의 대사, 내면 심리, 신체 행동을 임의 창작한 사칭이 발생했습니다.
-즉시 사칭을 중단하고 방금 사칭된 {user}의 발화와 행동을 전부 무효화하세요.
-오직 현장 NPC의 대사·행동과 주변 환경 묘사만으로, {user}가 개입할 여백을 남긴 채 직전 상황을 짧게 재출력하세요.
```

#### 4. `상태점검` (인물 속마음 및 무의식적 호감도 확인)
* **슬러그**: `status_check` | **이름**: `상태점검` | **설명**: `현장 인물들의 속마음과 호감도 점검`
```markdown
## status_check
- name: 상태점검
- description: 현장 인물들의 속마음과 호감도 점검
- prompt:
RP 일시 중단. 현장에 위치한 주연 인물들이 {user}를 바라보는 내면 상태를 관찰자 시점으로 브리핑한다.
-캐릭터들은 이 화면을 인지하지 못함.
-현장 인물당 아래 형식으로 1~2줄씩 출력:
·[인물명]: {user}를 향한 현재 속마음(경계/호감/의심), 말하지 못한 감정, 긴장도
-새로운 사건을 진행하지 않고 상태 브리핑만 출력할 것.
```

#### 5. `다음날로` (일정 마감 및 익일 타임스킵)
* **슬러그**: `next_day` | **이름**: `다음날로` | **설명**: `오늘 일정을 마감하고 다음 날로`
```markdown
## next_day
- name: 다음날로
- description: 오늘 일정을 마감하고 다음 날로
- prompt:
이번 응답에서 오늘 일정을 마감하고 다음 날 아침으로 전환한다.
-정리: 남은 인원의 퇴장, 거점 복귀, 취침까지를 2~3줄로 짧게 요약.
-계승: 관계 단계, 자원/부상 상태, 확정된 사실.
-초기화: 현장 일시 인원, 당일 소모품.
-다음 날 아침 시점의 > INFO와 새 상황을 출력하되, {user}의 첫 행동 여백을 남길 것. 모델 스스로 새 위기를 급발진시키지 말 것.
```

* **슬러그**: `board` | **이름**: `사내망` | **설명**: `익명 게시판 실시간 반응 확인`

## 4. 비가시적 런타임 조향 주석 (`[//]: # (...)`)

- **문법**: `[//]: # (지시 또는 상태 앵커)`
- **원리**: 마크다운 주석이므로 **플레이어 화면에는 완전히 투명하게 숨겨집니다.** 하지만 LLM은 이를 컨텍스트로 읽으므로, 다음 턴의 씬 분위기나 긴장도를 비가시적으로 제어할 수 있습니다.
- **예시**:
  - `[//]: # (Mood: Grim Tension | Rain: Heavy | Enemy: Lurking)`
  - `[//]: # (Pacing: Slow intimate romance | Focus: Breathing & Eye contact)`

## 5. 최종 빌드 검증 체크리스트 (Lint Checklist)

컴파일을 마치고 배포하기 전 다음 10가지를 최종 확인합니다:

- [ ] 1. **통합본 분량**: SAFE/UNSAFE 모두 7,000자 이하인가? (권장 6,200~6,800자)
- [ ] 2. **오프닝 분량**: 프롤로그와 시작 프롬프트가 각각 1,000자 이하인가?
- [ ] 3. **키워드북 분량**: 모든 키워드북 항목 본문이 UTF-16 기준 400자 이하인가?
- [ ] 4. **마침표 핵 배제**: 키워드북 트리거에 `.`이 포함된 항목이 없는가?
- [ ] 5. **부분문자열 충돌**: 키워드가 다른 단어의 부분문자열로 묻히지 않는가?
- [ ] 6. **상하단 하네스**: 상단 `> INFO`와 하단 ````UI````가 출력 계약에 정확히 명시되었는가?
- [ ] 7. **PC 주권 보호**: 유저 대사/생각 대필 금지 및 간접 인용 규칙이 존재하는가?
- [ ] 8. **발화자 상한**: 한 씬에서 동시 발화자 1~3명 상한이 명시되었는가?
- [ ] 9. **비피학적 현실저항 가드**: NPC의 입체적 자존감 방어 규칙이 들어있는가?
- [ ] 10. **스포일러 차단**: 상세설명/가이드에 비밀을 누설하지 않고 4대 플레이 팁으로 치환했는가?
